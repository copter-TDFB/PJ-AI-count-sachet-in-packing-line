# Auto-created invoices are posted immediately, not left as draft

When a Print-Bill Sale Order has zero Invoices, `test_odoo_counter_app.py` now creates one via Odoo's standard invoicing flow and validates/posts it in the same call, rather than leaving it as Draft for a human to review first. We chose this because a Draft invoice has no tax invoice number yet (`name` is `False` in Odoo until posted) and cannot be printed — leaving it as Draft would mean the feature never actually satisfies the original ask (auto-print the bill on scan). The trade-off: a posted invoice is legally final in Odoo and can only be corrected with a credit note, so if a bad pack count later implies a different invoiced quantity, undoing it costs more than editing a still-draft invoice would have. This is accepted for now, scoped to the test tenant only and only to orders with zero prior invoices — existing draft/cancelled invoices are explicitly left untouched (see `CONTEXT.md` → "Auto-invoice creation").
